= Get started with the gRPC server

`dengjen-tts-grpc` is a local gRPC server that loads dengjen-tts voices and streams synthesized audio
to any client that speaks gRPC. The https://github.com/ZirekHQ/dengjen-nvda[dengjen-nvda] screen-reader
add-on uses it this way.

== What is published

* GitHub release `grpc-release-v2.1.1`, asset `dengjen-tts-grpc-v2.1.1-windows-x64.zip`.
  It holds `dengjen-tts-grpc.exe` and `NOTICE`. ONNX Runtime is linked into the executable.
* The release is Windows x64 only. On other platforms, build from source with
  `cargo build --release -p dengjen-tts-grpc`. See xref:installation.adoc[Build from source].
* The executable needs the Microsoft Visual C{plus}{plus} runtime (it imports `VCRUNTIME140.dll`,
  `VCRUNTIME140_1.dll` and `MSVCP140.dll`). Install the
  https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist[Visual C{plus}{plus} Redistributable]
  if the server does not start.

== Install

In PowerShell:

[source,powershell]
----
curl.exe -LO https://github.com/ZirekHQ/dengjen/releases/download/grpc-release-v2.1.1/dengjen-tts-grpc-v2.1.1-windows-x64.zip
Expand-Archive dengjen-tts-grpc-v2.1.1-windows-x64.zip -DestinationPath dengjen-tts-grpc
----

== Prerequisites

* A voice. Download `en_US-lessac-low.onnx` and its manifest as shown in
  xref:start-python.adoc#prerequisites-a-voice[the Python page].
* The eSpeak-ng data. The zip does not contain it. The server looks for an `espeak-ng-data` folder next
  to the executable, so extract it there and set no environment variable. Releases after 2.1.1
  attach `dengjen-espeak-ng-data-<version>.tar.gz`, built from the pinned espeak-ng source:
+
[source,powershell]
----
tar -xzf dengjen-espeak-ng-data-<version>.tar.gz -C dengjen-tts-grpc
----
+
For 2.1.1 and earlier, take the older copy from the source tarball instead:
+
[source,powershell]
----
curl.exe -LO https://github.com/ZirekHQ/dengjen/archive/refs/tags/v2.1.1.tar.gz
tar -xzf v2.1.1.tar.gz --strip-components=3 -C dengjen-tts-grpc dengjen-2.1.1/deps/dev/espeak-ng-data
----

== Start the server

[source,powershell]
----
.\dengjen-tts-grpc\dengjen-tts-grpc.exe
----

The server binds `127.0.0.1` only. Version 2.1.1 prints `DENGJEN_GRPC_LISTENING port=<port>` on stdout
after it binds its port, and writes its log to stderr. Three environment variables change its behavior:

[cols="2,1,3"]
|===
|Variable |Default |Effect

|`DENGJEN_GRPC_SERVER_PORT`
|`49314`
|TCP port. `0` lets the OS pick a free port; read it from the `DENGJEN_GRPC_LISTENING` line. A value that is not a port number falls back to the default.

|`DENGJEN_GRPC`
|`info`
|Log filter, in the `tracing` `EnvFilter` syntax such as `debug`. A malformed value falls back to `info` with a warning.

|`DENGJEN_ESPEAKNG_DATA_DIRECTORY`
|the executable's directory
|Directory that _contains_ the `espeak-ng-data` folder.
|===

For example, `$env:DENGJEN_GRPC_SERVER_PORT = 0` before the command above picks a free port. The examples
below connect to `127.0.0.1:49314`. `call_sequence.sh` and `client.py` read `DENGJEN_GRPC_ADDRESS` (another `host:port`) to change that.

== Check that it works

The client steps below (the `curl` download, `bash call_sequence.sh`, `VAR=value command`, `ffmpeg`)
use a POSIX shell: Linux, macOS, or Git Bash on Windows. The server binds `127.0.0.1` only, so a client
in WSL2 cannot reach a server running on the Windows host. Run the client on the same host as the server.

`GetDengjenVersion` needs no voice. The server does not register gRPC reflection, so grpcurl needs the
`.proto` file. Install https://github.com/fullstorydev/grpcurl[grpcurl], then run:

[source,sh]
----
curl -LO https://raw.githubusercontent.com/ZirekHQ/dengjen/v2.1.1/crates/frontends/grpc/proto/dengjen_grpc.proto
grpcurl -plaintext -import-path . -proto dengjen_grpc.proto -d '{}' \
    127.0.0.1:49314 dengjen_grpc.DengjenGrpc/GetDengjenVersion
----

If the server runs on another port, for example after `DENGJEN_GRPC_SERVER_PORT=0`, replace `49314` in
that command.

`examples/grpc/call_sequence.sh` in the https://github.com/ZirekHQ/dengjen[repository] makes the same
call through a `call` function that adds the grpcurl flags and the address:

[source,sh]
----
include::example$grpc/call_sequence.sh[tag=version]
----

The reply carries the server version, which equals the release version:

[source,json]
----
{
  "version": "2.1.1"
}
----

Install https://jqlang.org/[jq] as well, then copy the script
from the repository next to `dengjen_grpc.proto` (or set `DENGJEN_PROTO_DIR` to the directory that holds

----

`SynthesizeUtterance` streams one chunk per sentence. grpcurl prints each chunk's `audioBytes` as base64,
and the script decodes them into one file:

[source,sh]
----
include::example$grpc/call_sequence.sh[tag=synthesize]
----

The script prints the version JSON from the first call, then the voice key and the output size. The
last two lines look like this, for example:

----
voice_key=aa3cceca7d5a09d3
wrote output.pcm (67072 bytes)
----

The audio is raw 16-bit little-endian PCM with no WAV header, mono, at the voice's sample rate
(`audio.sampleRate` in the `LoadVoice` reply, 16000 for `en_US-lessac-low`). The byte count changes from
run to run. To get a playable file:

[source,sh]
----
ffmpeg -f s16le -ar 16000 -ac 1 -i output.pcm output.wav
----

== The RPCs

[cols="2,3"]
|===
|RPC |What it does

|`GetDengjenVersion`
|Returns the server version.

|`LoadVoice`
|Loads a voice manifest and returns its `VoiceDescriptor` with a `voice_key`. Loading the same path again returns the loaded voice.

|`GetVoiceInfo`
|Returns the `VoiceDescriptor` of a loaded voice: audio format, speakers, language, `supports_streaming_output`.

|`GetSynthesisOptions`
|Returns a loaded voice's default synthesis settings.

|`SetSynthesisOptions`
|Changes those defaults: `speaker`, `length_scale`, `noise_scale`, `noise_w` and a `parameters` map.

|`SynthesizeUtterance`
|Streams `SynthesisChunk` messages of PCM with a `real_time_factor`, one per sentence in `MODE_LAZY`.

|`SynthesizeUtteranceRealtime`
|Streams `RealtimeAudioChunk` messages of PCM windows for voices that support streaming.

|`Recognize`
|Takes `pcm_s16le` (mono 16-bit little-endian PCM) and `sample_rate`, and returns the transcript `text`. Available in builds with the `stt` feature and a configured model.
|===

`SynthesisRequest.synthesis_mode` picks `MODE_LAZY`, `MODE_PARALLEL` or `MODE_BATCHED`. See
xref:streaming.adoc[Streaming synthesis and the gRPC frontend] for how the modes differ.

The release archives for Linux, macOS and Windows include the recognizer libraries; see xref:speech-recognition.adoc[Speech recognition]. To enable `Recognize`, set `DENGJEN_GRPC_STT_MODEL_DIR` and `DENGJEN_GRPC_STT_MODEL_SHA256` together. The server exits at startup if the checksum does not match.

== Errors

An RPC that names a voice that is not loaded returns `NotFound`, and so does `LoadVoice` with a manifest
path that does not exist. For the first case, see the example in
xref:streaming.adoc[Streaming synthesis and the gRPC frontend].

`Recognize` returns `InvalidArgument` for empty audio, audio shorter than 25 ms, an odd byte count or a sample rate that is zero or above `i32::MAX`. It returns `FailedPrecondition` when no model is configured, `ResourceExhausted` while all recognition slots (`DENGJEN_GRPC_MAX_CONCURRENT_RECOGNITION`) are busy, and `Internal` when decoding fails.
